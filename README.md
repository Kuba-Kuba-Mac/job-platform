# Стажировки KG — платформа поиска работы и стажировок

Веб-приложение для студентов, выпускников и местных компаний: соискатель ведёт резюме и откликается на вакансии, работодатель публикует вакансии и обрабатывает отклики.

Групповой проект, команда из 3 человек.

## Стек

| Слой | Технологии |
|---|---|
| Backend | Django 5 + Django REST Framework, JWT (simplejwt), Argon2 |
| База данных | PostgreSQL 16 |
| Frontend | React 18 + Vite |
| Инфраструктура | Docker Compose, GitHub Actions |
| Документация API | Swagger (drf-spectacular) |

## Быстрый старт (одной командой)

```bash
cp .env.example .env
docker compose up --build
```

- Frontend: http://localhost:5173
- API: http://localhost:8000/api/
- Swagger: http://localhost:8000/api/docs/
- Админка Django: http://localhost:8000/admin/ (вход `admin@demo.kg`, см. ниже)
- Почта (Mailpit): http://localhost:8025 — сюда приходят все письма платформы (подтверждение email, сброс пароля)

Перед первым запуском замените `DJANGO_SECRET_KEY` в `.env` на случайную строку: `make secret`.

### Демо-данные

При `SEED_DEMO=true` (по умолчанию в `.env.example`) backend при старте создаёт вымышленные данные: 4 компании (одна на модерации), 15 вакансий (12 опубликованных, одна на модерации, одна отклонённая с причиной, одна в архиве), 3 соискателя с резюме, профилями и проектами, 7 откликов во всех статусах (отправлен, просмотрен, приглашение, отказ), избранное и один заблокированный пользователь. Повторный запуск ничего не дублирует. Все люди и резюме вымышленные.

| Роль | Email | Пароль |
|---|---|---|
| Администратор | `admin@demo.kg` | `Demo-Pass-2026` |
| Работодатель | `employer@demo.kg` (ещё `employer2…4@demo.kg`) | `Demo-Pass-2026` |
| Соискатель | `seeker@demo.kg` (ещё `seeker2@demo.kg`, `seeker3@demo.kg`) | `Demo-Pass-2026` |
| Заблокированный соискатель (A-01) | `seeker4@demo.kg` — при входе видит сообщение о блокировке | `Demo-Pass-2026` |

`make seed` — добавить демо-данные вручную, `make reseed` — удалить всех пользователей `@demo.kg` и создать заново (другие данные не трогаются).

### Почта

Если задан `EMAIL_HOST`, письма уходят по SMTP; в Docker это Mailpit (`EMAIL_HOST=mailpit`, `EMAIL_PORT=1025`), который ничего не отправляет наружу и показывает письма в браузере. Без `EMAIL_HOST` письма печатаются в консоль backend. Ссылки в письмах ведут на `FRONTEND_URL`.

### Без Docker (только backend)

```bash
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
python manage.py migrate        # без POSTGRES_HOST используется SQLite
python manage.py test
python manage.py runserver
```

**Скорость поиска** (требование ТЗ: < 2 с при 1000 вакансий). `python manage.py benchmark_search` создаёт 1000 вымышленных вакансий, прогоняет типичные запросы через настоящий view и откатывает данные. PostgreSQL 16 в Docker, 1012 опубликованных вакансий, 5 повторов:

| Запрос | Найдено | Медиана, мс | Макс, мс | SQL-запросов |
|---|---|---|---|---|
| без фильтров | 1012 | 4.8 | 7.0 | 3 |
| город | 111 | 4.0 | 4.6 | 3 |
| зарплата от 50 000 | 544 | 4.3 | 4.3 | 3 |
| опыт + занятость + график | 98 | 4.3 | 4.8 | 3 |
| только стажировки | 298 | 4.0 | 5.2 | 3 |
| текст «python» | 411 | 9.2 | 10.3 | 3 |
| всё сразу, по зарплате | 2 | 3.6 | 3.9 | 3 |
| страница 10 | 1012 | 5.5 | 19.0 | 3 |

Худший ответ — 19 мс. Число SQL-запросов не зависит от числа результатов (индексы на поля фильтров, `select_related`/`prefetch_related`, избранное и статус отклика — аннотациями); это проверяют тесты с `assertNumQueries`.

## API

| Метод | URL | Кто | Описание |
|---|---|---|---|
| POST | `/api/auth/register/` | все | регистрация `{email, password, role}`, отправляет письмо подтверждения |
| POST | `/api/auth/login/` | все | вход → `{access, refresh, user}` |
| POST | `/api/auth/refresh/` | все | обновить access-токен |
| POST | `/api/auth/logout/` | авторизованный | выход, refresh в чёрный список |
| GET/PATCH | `/api/auth/me/` | авторизованный | «Мой профиль»: `full_name`, `phone`, `city`, `email` (role и email_verified только для чтения) |
| POST | `/api/auth/password/change/` | авторизованный | смена пароля `{old_password, new_password}` → новая пара `{access, refresh}`, старые refresh отзываются |
| POST | `/api/auth/verify-email/` | все | подтвердить email `{uid, token}` из письма |
| POST | `/api/auth/verify-email/resend/` | авторизованный | отправить письмо подтверждения ещё раз (400, если уже подтверждён) |
| POST | `/api/auth/password/reset/` | все | «Забыли пароль?» `{email}` — ответ одинаковый для любого email |
| POST | `/api/auth/password/reset/confirm/` | все | новый пароль `{uid, token, new_password}`, отзывает все refresh-токены |
| GET | `/api/companies/` | все | одобренные компании |
| GET/POST/PATCH | `/api/companies/me/` | работодатель | свой профиль компании |
| GET/POST | `/api/resumes/` | соискатель | свои резюме |
| GET/PATCH/DELETE | `/api/resumes/{id}/` | соискатель | одно своё резюме |
| GET | `/api/skills/?q=py` | все | подсказки навыков |
| GET/POST | `/api/vacancies/my/?archived=true\|false` | работодатель | свои вакансии; создание требует профиля компании |
| GET/PATCH | `/api/vacancies/my/{id}/` | работодатель | своя вакансия; правка возвращает на модерацию, DELETE нет |
| POST | `/api/vacancies/my/{id}/archive/`, `…/restore/` | работодатель | в архив / из архива |
| GET | `/api/vacancies/?q=&city=&salary=&experience=&employment_type=&schedule=&internship=true&ordering=new\|salary&page=` | все | поиск опубликованных вакансий (S-02); experience, employment_type, schedule — через запятую |
| GET | `/api/vacancies/cities/` | все | города с опубликованными вакансиями для фильтра |
| GET | `/api/vacancies/{id}/` | все | страница вакансии с данными компании (S-03); для соискателя — `favorite_id` и `application_status` |
| GET | `/api/vacancies/my/{id}/applications/?status=` | работодатель | отклики на свою вакансию (E-03) |
| GET/PATCH | `/api/profiles/me/` | соискатель | свой профиль студента (создаётся при первом обращении) |
| GET/POST/PATCH/DELETE | `/api/profiles/me/projects/` | соискатель | свои проекты (до 20) |
| GET | `/api/profiles/{user_id}/` | работодатель, админ, сам соискатель | профиль студента без email и телефона |
| GET/POST/DELETE | `/api/favorites/`, `/api/favorites/{id}/` | соискатель | избранное `{vacancy_id}`; повторно — 400 (S-06) |
| GET/POST | `/api/applications/?status=` | соискатель | «Мои отклики» и отклик `{vacancy_id, resume_id, cover_letter}` (S-04, S-05) |
| GET | `/api/applications/{id}/` | соискатель | свой отклик |
| GET | `/api/employer/applications/{id}/` | работодатель | отклик с полным резюме; новый становится «просмотрен» (E-03) |
| POST | `/api/employer/applications/{id}/status/` | работодатель | `{status: viewed\|invited\|rejected}` (E-04) |
| GET | `/api/admin/users/?q=&role=&is_active=` | администратор | пользователи (A-01) |
| POST | `/api/admin/users/{id}/block/`, `…/unblock/` | администратор | блокировка `{reason}` / разблокировка |
| GET | `/api/admin/moderation/vacancies/?status=`, `/api/admin/moderation/companies/?status=` | администратор | очередь модерации, по умолчанию `pending` (A-02) |
| POST | `…/moderation/{vacancies\|companies}/{id}/approve/`, `…/reject/` | администратор | одобрить / отклонить `{reason}` |

Полное описание — в Swagger: `/api/docs/`.
